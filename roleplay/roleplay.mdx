## Overview

Petto's roleplay commands are small, friendly interactions. They use the configured prefix and accept an optional member. If no member is supplied, the response describes the action as self-directed.

<CodeGroup>

```javascript Commands
!airkiss  !angrystare  !bite  !bleh  !blush  !boop
!brofist  !cry  !cuddle  !dance  !glomp  !handhold
!happy  !highfive  !hug  !kill  !kiss  !lick
!nom  !pat  !poke  !punch  !slap  !smile
!smug  !tickle  !wave  !wink  !yeet
!hi  !bye  !yes  !no  !laugh  !sad  !angry
```

```javascript Examples
!hug @Friend
!boop @Someone
!lick @Friend
!dance
!hi @Friend
!yes @Friend
```

</CodeGroup>

Each interaction returns a randomized image when the provider has one available. Petto uses safe, non-explicit wording in the message and falls back between image providers when a source is unavailable. Roleplay is separate from moderation, so names such as `kick` cannot replace moderation commands.

When an interaction targets another member, the embed shows the recipient's running counter in italic text below the action, for example `forky has received 2 hugs.` It includes an action-specific response button such as **Hug back** and a **Reject** button. Only the mentioned member can use them, and the first response disables both buttons. The response button returns the same action to the sender; **Reject** replies with a `slap` interaction. The response is counted per server, user, and action. The counters are atomic and require the current roleplay tables/functions from `src/db/schema.sql` to be applied.

## Notes

Roleplay interactions are intended for normal server members and do not change roles, permissions, or moderation cases. A server can disable any command with the regular command-disable configuration if a particular interaction is not wanted.
