## Overview

Logging routes independent event categories to their own channels, so a mod-log channel isn't one unreadable firehose. Each category can go to a different channel, or be left off entirely.

## The categories

`messages` · `members` · `roles` · `channels` · `invites` · `emojis` · `voice` · `server` · `sanctions` · `verification` · `automod`

## Commands

<CodeGroup>

```javascript Syntax
/logs view
/logs add <channel> <event>
/logs remove <channel> [event]
```

```javascript Example
/logs add channel:#mod-log event:sanctions
/logs add channel:#member-log event:members
/logs remove channel:#mod-log
```

```javascript Prefix
!logs add #mod-log sanctions
```

</CodeGroup>

Omitting `event` on `/logs remove` clears every category routed to that channel at once.

## Per-channel color override

<CodeGroup>

```javascript Syntax
/logs color set <channel> <event> <color>
/logs color list <channel>
```

```javascript Example
/logs color set channel:#mod-log event:sanctions color:#ff0000
```

</CodeGroup>

## Ignoring users or channels

<CodeGroup>

```javascript Syntax
/logs ignore toggle [user] [channel]
/logs ignore list
```

```javascript Example
/logs ignore toggle user:@TrustedBot
```

</CodeGroup>

<Tip>
  A user or channel added to the ignore list is skipped by every logging category at once, not just one, useful for bots or a staff-only channel you don't want cluttering the log.
</Tip>

For word filters, anti-spam, and anti-raid, see [Automod](/moderation/automod).
